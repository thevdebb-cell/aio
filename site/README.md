# Star Customs — Download Site (Netlify)

Branded, secure download portal for completed orders. It verifies the expiring
link the bot generates, then hands out a short-lived Supabase signed URL and
redirects the buyer to their file.

## How it fits together

```
buyer's DM link                Netlify function                 Supabase Storage
/dl?id=SC-...&t=exp.sig  ─────▶  verify HMAC + expiry  ─────▶  createSignedUrl(120s) ─▶ file
```

The bot and this site share one secret (`DOWNLOAD_SECRET`) so only links the bot
signed will work, and only until they expire.

## Requirements

- The bot must run with `FILE_DRIVER=supabase` (files live in Supabase Storage).
- Set the bot's `SITE_BASE_URL` to this site's URL so delivery links point here.

## Deploy

1. Create a site on [Netlify](https://app.netlify.com) → **Add new site** →
   deploy this `site/` folder (drag-and-drop the folder, or connect the repo and
   set the base directory to `site`).
2. Netlify auto-installs `@supabase/supabase-js` from `package.json` and picks up
   `netlify.toml` (publish `.`, functions in `netlify/functions`).
3. In **Site settings → Environment variables**, add:
   | Key | Value |
   | --- | --- |
   | `DOWNLOAD_SECRET` | the **same** value as the bot's `DOWNLOAD_SECRET` |
   | `SUPABASE_URL` | your Supabase project URL |
   | `SUPABASE_SERVICE_KEY` | Supabase **service role** key (keep secret) |
   | `SUPABASE_BUCKET` | `orders` (or your bucket name) |
4. Redeploy. Copy the site URL (e.g. `https://star-customs-orders.netlify.app`)
   and set it as `SITE_BASE_URL` in the bot's `.env`.

## Test

Open `https://<your-site>/` — you should see the branded portal. A real `/dl`
link is generated by the bot on delivery; expired or tampered links show a clear
message instead of a file.

## Security notes

- The `SUPABASE_SERVICE_KEY` lives only in Netlify's server-side function env —
  it is never sent to the browser.
- Links are HMAC-signed and time-limited; the final Supabase URL is valid for
  only 120 seconds.
